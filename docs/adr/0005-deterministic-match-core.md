# ADR-0005: Детерминированное ядро матча и предел внутренних событий

- Статус: принято к проверке владельцем
- Дата: 17 октября 2026 года
- Решение: владелец проекта dKorialstrasz после review PR задачи #10
- Связанные требования: RULE-01–05, RULE-07–09, RULE-12–15, NFR-01–02, AC-04
- Связанная задача: [#10](https://github.com/dKorialstrasz/response-online/issues/10)
- Учитывает: [ADR-0003](0003-serialized-match-execution.md)

## Контекст

Authoritative backend должен воспроизводимо выполнять базовый жизненный цикл
партии. Порядок обхода `map`, системное время и внешняя случайность не могут
менять результат. Ошибка команды не должна оставлять частичную оплату или
перемещение, а ошибочная либо зацикленная цепочка не должна занимать owner матча
неограниченно.

Официальная страница [«Правила»](https://response-game.ru/rules) сверена
17.10.2026. Она не публикует отдельный номер редакции, поэтому неизменяемый pin
ядра называется `response-rules-2026-10-17`. Этот pin относится к реализованной
матрице базового цикла; карточные EffectSpec и спорные взаимодействия остаются
воротами #11/#12 и не считаются автоматически решёнными.

## Решение

Состояние хранится как детерминированные структуры и упорядоченные списки.
`Match.Handle` клонирует состояние, применяет одну команду, проверяет инварианты
после внутренних событий и фиксирует клон только целиком. Ошибка оставляет
исходный state и RNG cursor без изменений.

Seed и стартовое время передаются при создании матча. Состояние PRNG и cursor
входят в закрытый audit state. Версии content/decks/effectSpec/rules/protocol/
engine копируются в матч и входят в canonical state hash. Replay использует тот
же initial config и принятые команды.

Переход между зонами увеличивает `generation` и создаёт новый `zoneObjectId`.
`instanceId` остаётся только audit-идентичностью. Старый `ObjectRef` не разрешается
после перемещения.

Один `MatchSession` на матч отправляет команды через mailbox ADR-0003. Engine не
предоставляется transport handler напрямую.

Предел — 10 000 внутренних событий на одну команду. Превышение атомарно
завершает матч как `aborted_technical`, без победителя, и сохраняет закрытый
diagnostic trace. Это техническая защита, не правило ничьей. Предел задаётся в
config только для детерминированных тестов; runtime использует значение по
умолчанию.

## Граница решения

Ядро реализует подготовку, пересдачу, фазы, бюджет действий/пасы, базовые
столкновения, Приказы, поражение при отсутствии Приказа и восстановление.
Конкретные card abilities, trigger queue, pending-choice producers, Обход и иные
ключевые слова реализуются в #11/#12 по подтверждённым EffectSpec. Команда
`commit_action` означает только успешную фиксацию уже проверенного будущим
rule-handler действия; она не является публичной командой протокола.

## Последствия

- Один input/seed/version set даёт одинаковый state hash.
- Ошибка или stale revision не меняет state.
- Runaway завершает только свой матч контролируемым техническим результатом.
- Любое изменение алгоритма PRNG, автомата или canonical state требует новой
  `engineVersion` и обновления golden hash.
- Нельзя называть M1 rules-complete до закрытия #11/#12 и подписания полной
  conformance-матрицы.
