# ADR-0006: Анонимные сессии и атомарные комнаты

- Статус: принято к проверке
- Дата: 17 октября 2026 года
- Решение: владелец проекта dKorialstrasz после review/приёмки
- Связанные требования: FR-01–10, UC-01–03, SEC-02, AC-03
- Связанная задача: [#13](https://github.com/dKorialstrasz/response-online/issues/13)
- Учитывает: [ADR-0001](0001-in-memory-match-state.md),
  [ADR-0003](0003-serialized-match-execution.md),
  [ADR-0005](0005-deterministic-match-core.md)

## Контекст

Код комнаты нужен для приглашения, но не может восстанавливать занятое место.
Create/join, готовность и старт конкурируют между запросами и не должны создавать
лишние комнаты, третье место или два матча. M1 хранит состояние только в памяти,
но обязан различать неверный и просроченный код, заполненную комнату и потерянную
сессию. Сетевой контракт и cookie/CSRF/Origin policy реализованы в #14 согласно
ADR-0008.

## Решение

`RoomService` является единственным владельцем изменяемого состояния анонимных
сессий и лобби. Один mutex образует транзакционную границу для create/join,
изменения выбора, ready/start, connection replacement и TTL cleanup. После старта
изменение матча выполняет отдельный `MatchSession` с owner/mailbox из ADR-0003.

- Секрет восстановления создаётся из 32 случайных байтов (256 бит) и возвращается
  только при создании сессии. В памяти хранится SHA-256 digest; сравнение выполняется
  constant-time. Любой неверный, неизвестный, отозванный или истёкший секрет даёт
  одну безопасную причину `ErrSessionLost`.
- Срок сессии — 24 часа со sliding extension после успешной аутентификации или
  авторизации управляющего соединения. Room code не участвует в аутентификации.
- Код комнаты — 13 символов RFC 4648 base32 без padding, то есть 65 случайных бит.
  Коллизии проверяются и с активными кодами, и с tombstone. Каталог комнат не
  предоставляется.
- Idempotency key ограничен 128 символами, scoped к session и операции. Повтор
  create/join возвращает прежнюю комнату/место; повтор ключа для другого вида
  операции или другого кода отклоняется. Записи живут не дольше in-memory сессии.
- Комната содержит ровно два фиксированных места без особых полномочий создателя.
  Уход любого участника не удаляет второго. Зеркальные deckId разрешены.
- Изменение deckId или перестановки пяти Приказов сбрасывает ready изменившего
  участника. Второй ready транзакционно проверяет обе сессии и один immutable
  content snapshot, создаёт единственный engine match, применяет обе перестановки
  Приказов и только затем публикует состояние active. Ошибка не фиксирует частичный
  ready или match.
- Runtime pin provider при загрузке проверяет SHA-256 CardDefinition и всех шести
  deck manifests из release descriptor. Match хранит шесть version fields и точные
  `path#sha256` обоих manifests; raw client deck list не принимается.
- Пустая waiting-комната истекает через 15 минут, непустое неактивное лобби — через
  30 минут. Успешная операция участника считается активностью. Active match не
  удаляется lobby cleanup. `RunCleanup` вызывает очистку, а `WaitForRoomChange`
  завершается `ErrRoomExpired`, поэтому ожидающий запрос не остаётся подвешенным.
- Удалённые roomId/code сохраняются только как in-memory tombstone на 24 часа.
  Это позволяет отличить просроченный код от никогда не существовавшего без
  сохранения состава комнаты. После tombstone код снова может использоваться.
- Одноразовый connection ticket содержит 256 случайных бит, хранится только как
  digest и действует 30 секунд. Redeem атомарно удаляет ticket. Новое connectionId
  повышает generation места; прежний lease немедленно получает
  `ErrConnectionReplaced`. Отзыв/истечение сессии даёт `ErrSessionLost`.

## Security boundaries

`RoomSnapshot` — allowlist: roomId/code/status/revision, занятость и ready обоих
мест, собственное место/выбор и безопасные match pins. Он не содержит секретов,
sessionId, connectionId, выбора соперника, seed или raw engine state. Сервис не
логирует входы. HTTP status/error body, cookie, CSRF, Origin/CORS, rate limits,
WebSocket frame и PlayerView определяются и проверяются в #14, а reconnect budget
и технические исходы — в #15.

## Последствия

- Гонки одного процесса устраняются простой проверяемой транзакцией; разные матчи
  после старта по-прежнему имеют независимые owners.
- Pin provider вызывается внутри start-транзакции и обязан быть локальным,
  неизменяемым и неблокирующим; файловая реализация полностью загружается заранее.
- In-memory idempotency, tombstone и сессии теряются при restart согласно ADR-0001.
  Durable recovery не обещается.
- 65 бит room code соответствуют FR-04, но не заменяют rate limits из #14.

## Рассмотренные альтернативы

- Код комнаты как bearer credential отклонён: он позволил бы захватить место по
  invitation URL.
- Хранение cleartext session secret/ticket отклонено из-за риска утечки памяти и
  диагностики.
- Отдельные mutex на комнаты отклонены для M1: глобальная транзакция проще
  доказывает атомарность admission/start; profiling #21 определит, нужен ли sharding.
- Автоматическое освобождение места сразу после истечения сессии отклонено: это
  смешивает session loss с leave/forfeit, политика которых относится к #15.
